## 00 — 游戏王 OCG 游戏本体认知

*（源：`docs/llmstudy/00-game-overview.md`）*

> **撰写日期**：2026-07-28
> **来源优先级**：P0 官方 → P1 YGOrg/yugipedia → P2 简中 wiki
> **环境**：本知识库聚焦 **OCG（Official Card Game，亚洲区）**，不涉及 TCG（欧美）特殊裁定。

---

### 1. 游戏王 OCG 是什么

**游戏王 Official Card Game（遊☆戯☆王OCG）** 是由 KONAMI 发行的集换式卡牌游戏（TCG），基于漫画《游戏王》中的决斗怪兽（Duel Monsters）玩法。OCG 是游戏王在**亚洲地区**（日本、中国大陆、韩国、东南亚等）发行的版本。

#### 与 TCG 的区别

| | OCG | TCG |
|---|---|---|
| 发行区域 | 日本、亚洲 | 北美、欧洲、大洋洲 |
| 卡片语言 | 日文、简中、韩文 | 英文、法文、德文等 |
| 卡池发布节奏 | 先于 TCG 约 3-6 个月 | 滞后 |
| 禁限卡表 | 独立维护 | 独立维护 |
| 裁定 | 以日文 KONAMI Q&A 为准 | 有部分独立裁定 |
| 卡片罕贵度 | 不同分布 | 不同分布 |

> **本项目完全基于 OCG 规则和裁定**。不使用 TCG 特有的裁定或禁限卡表。

#### Master Duel

**Master Duel** 是 KONAMI 的官方电子游戏平台（PC/主机/手机），采用独立的禁限卡表和部分简化规则（如无 BO3 side deck）。本项目也不涉及 Master Duel 的特殊处理。

---

### 2. 游戏的基本规则

- **对战人数**：2 人（1v1）
- **卡组**：主卡组 40-60 张，额外卡组 0-15 张，副卡组 0-15 张
- **同名卡限制**：主卡组 + 额外卡组 + 副卡组合计最多 3 张同名卡
- **初始 LP（生命值）**：8000
- **初始手牌**：5 张（先攻第一回合不抽卡）

#### 胜利条件

1. 将对方 LP 降至 0
2. 对方需要抽卡时卡组无卡可抽
3. 特定卡片效果的特殊胜利条件（如"艾克佐迪亚"）

#### 比赛结构

- **一场 Duel（决斗）**：单局对战
- **一场 Match（比赛）**：BO3（三局两胜），每局之间可以换副卡组

---

### 3. 大师规则（Master Rule）演进

游戏王 OCG 的规则体系称为**大师规则（Master Rule）**，经历了多次重大修订：

| 版本 | 时间 | 核心变化 |
|---|---|---|
| 大师规则 1 | 2008.03 | 术语统一，Speed Spell 体系确立 |
| 大师规则 2 | 2011.03 | 超量召唤（Xyz）引入，优先权概念调整 |
| 大师规则 3 | 2014.03 | 灵摆召唤（Pendulum）引入，场地魔法共存规则改变 |
| 新大师规则 | 2017.03 | 连接召唤（Link）引入，EX 怪兽区域新增，EX 卡组特召必须到 EX 区或连接端 |
| **大师规则 (2020.04 修订)** | **2020.04** | **当前使用版本**。融合/S/X 怪兽可以直接出在主怪兽区；诱发效果场所移动规则改写 |

#### 2020 年 4 月修订的关键变化（OCG）

1. **额外卡组特召规则放宽**：融合/同调/超量怪兽从 EX 卡组特召时，可直接放在主怪兽区域（不再强制连接端）。
2. **诱发效果场所移动**：如果一张卡在满足发动条件后、效果发动前移动了位置，效果不再发动。
3. **召唤限制计数规则**：被无效的召唤不计入"本回合已经召唤过"的计数。
4. **同名特召次数限制**：被无效的特召不计入"XX 1 回合只能特召 1 次"。
5. **陷阱怪兽区域释放**：变成怪兽特殊召唤的永续陷阱卡，不再占用原来的魔陷区域。

> **本项目数据基于该版本规则**。

## 01 — 卡牌类型体系

*（源：`docs/llmstudy/01-card-types.md`）*

> **撰写日期**：2026-07-28
> **来源**：P0 KONAMI 官方规则书 + P2 `ocg-rule.readthedocs.io`
> **对应项目 case**：全部 58 条 case 的 `card_type` / `monster_type` / `spell_type` / `trap_type` 字段

---

### 1. 三大基础类型

游戏王卡片在规则上分为三大类：

```
怪兽卡 (Monster Card) ─── 橙色/蓝色/白色/黑色/绿色等底色
魔法卡 (Spell Card)    ─── 绿色底色，卡名右侧有「魔」标识
陷阱卡 (Trap Card)     ─── 紫色底色，卡名右侧有「罠」标识
```

每种在场上放置的位置和方式不同：
- **怪兽卡**：放置在怪兽区域（Main Monster Zone 或 Extra Monster Zone）
- **魔法卡**：放置在魔法&陷阱区域（或场地区域/灵摆区域）
- **陷阱卡**：放置在魔法&陷阱区域（盖放后下回合才能发动）

---

### 2. 怪兽卡（Monster Card）

#### 2.1 怪兽卡的属性字段

每张怪兽卡包含以下核心属性（对应本项目 Schema 中的 `card` 对象）：

| 字段 | 本项目 Schema 字段 | 说明 |
|---|---|---|
| 卡名 | `name` | 怪兽名称 |
| 属性 | `attribute` | 地/水/炎/风/光/暗/神 |
| 种族 | `race` | 龙/战士/魔法师/机械等 25 种族之一 |
| 等级/阶级/LINK | — | 怪兽的等级（星数）或 Link 值 |
| 攻击力/守备力 | — | ATK / DEF |
| 种类/能力 | `monster_type` | 通常/效果/融合/仪式/同调/超量/灵摆/连接 |
| 表示形式 | `status` + `position` | `face_up`/`face_down` + `attack`/`defense` |

#### 2.2 怪兽种类（Monster Type）枚举

本项目 Schema 中 `monster_type` 的完整枚举：

| 枚举值 | 分类 | 说明 | 对应 case 示例 |
|---|---|---|---|
| `normal` | 通常怪兽 | 无效果的黄色怪兽。灵摆通常怪兽也属于此类 | — |
| `effect` | 效果怪兽 | 有效果的橙色怪兽（占绝大多数） | 灰流丽 (case_001)、增殖的 G (case_006) |
| `fusion` | 融合怪兽 | 紫色卡，从 EX 卡组融合召唤 | 赫焉龙 (case_005) |
| `ritual` | 仪式怪兽 | 蓝色卡，通过仪式魔法召唤 | — |
| `synchro` | 同调怪兽 | 白色卡，调整+非调整同调召唤 | — |
| `xyz` | 超量怪兽 | 黑色卡，叠放召唤（RANK 代替 LV） | 编号38 (case_026) |
| `link` | 连接怪兽 | 深蓝色卡，连接召唤（LINK 值代替 DEF） | S:P 小夜骑士 (case_003) |
| `toon` | 卡通怪兽 | 特殊分类，有卡通世界依赖 | 卡通怪兽 (case_040/043) |
| `pendulum` | 灵摆怪兽 | 半绿半橙，可当怪兽也可以当魔法卡发动 | case_024, case_027 |

> **注意**：Schema 中的 `monster_type` 捕捉的是怪兽的召唤种类标签。一张融合怪兽如果同时是效果怪兽，其 `card_type` = `monster`，`monster_type` = `fusion`，效果文本另行描述。

#### 2.3 效果怪兽的效果分类（OCG 规则层面）

OCG 规则将怪兽效果分为 **5 类**：

| 分类 | 日文 | 说明 | 入连锁？ |
|---|---|---|---|
| **起动效果** | 起動効果 | 自己主要阶段主动发动（"1 回合 1 次，……才能发动"） | 是 |
| **诱发效果** | 誘発効果 | 满足条件时自动发动（"……的场合/时发动"） | 是 |
| **诱发即时效果** | 誘発即時効果 | 对方回合也能发动的效果（"对方回合也能发动"），咒文速度 2 | 是 |
| **永续效果** | 永続効果 | 只要在场就持续适用，不发动（如 Skill Drain） | 否 |
| **无种类效果** | 分類されない効果 | 不属于以上四类（如"这张卡不能通常召唤"、规则文本） | 否 |

> 本项目 58 条 case 中，大量涉及起动效果和诱发效果的发动合法性判断。

### 3. 魔法卡（Spell Card）

#### 3.1 魔法卡的子类

本项目 Schema 中 `spell_type` 的枚举：

| 枚举值 | 图标标识 | 咒文速度 | 说明 | 对应 case 示例 |
|---|---|---|---|---|
| `normal_spell` | 无 | 1 | 主要阶段发动，处理后送墓 | — |
| `quick_play_spell` | 速攻 | 2 | 对方回合也能发动，盖放后下回合可用 | 墓穴指名者 (case_025) |
| `continuous_spell` | 永 | 1 | 发动后留在场上持续适用 | 联合机库 (case_011) |
| `equip_spell` | 装 | 1 | 装备给怪兽，持续适用 | 大搜捕 (case_020) |
| `field_spell` | 场 | 1 | 放置在场地区域（不是魔陷区） | 完美卡通世界 (case_040) |
| `ritual_spell` | 仪 | 1 | 用于仪式召唤 | — |

#### 3.2 魔法卡的发动限制

- 通常/装备/永续/场地/仪式魔法：只能在**自己主要阶段**发动（咒文速度 1）
- 速攻魔法：可以在**任意阶段**发动（咒文速度 2），盖放的速攻魔法在盖放回合不能发动
- 魔法卡的一般发动流程：从手牌放到魔陷区 → 支付 cost → 选择对象 → 发动 → 效果处理

---

### 4. 陷阱卡（Trap Card）

#### 4.1 陷阱卡的子类

| 枚举值 | 图标标识 | 咒文速度 | 说明 | 对应 case 示例 |
|---|---|---|---|---|
| `normal_trap` | 无 | 2 | 盖放后下回合可发动，处理后送墓 | 无限泡影 (case_002)、神之通告 (case_004) |
| `continuous_trap` | 永 | 2 | 发动后留在场上持续适用 | 技能抽取 (case_015, case_018) |
| `counter_trap` | 反 | 3 | 最高咒文速度，只能被反击陷阱连锁 | 神之警告 (case_023) |

#### 4.2 陷阱卡的特殊规则

- **必须盖放**：陷阱卡必须先盖放（Set）到魔陷区，盖放回合不能发动
- **反击陷阱**：咒文速度 3，只有反击陷阱能连锁反击陷阱
- **陷阱怪兽**：部分永续陷阱卡发动后可以变成怪兽特殊召唤到怪兽区域（如"阿匹卜之化神"），此时原魔陷区域被释放可用

---

### 5. 灵摆怪兽（Pendulum Monster）的特殊性

灵摆怪兽是独特的"半怪兽半魔法"类型：
- 可以作为**怪兽**通常召唤/特殊召唤到怪兽区域
- 也可以作为**魔法卡**放置在灵摆区域（魔陷区的最左和最右）
- 在灵摆区域时，使用其灵摆效果（不是怪兽效果）
- 场上被破坏时不去墓地，而是**表侧表示加入额外卡组**

> 本项目 case_024 涉及灵摆怪兽送墓 cost 的问题——场上灵摆怪兽无法送墓，因此不能支付送墓 cost。

## 02 — 场地与区域模型

*（源：`docs/llmstudy/02-field-and-zones.md`）*

> **撰写日期**：2026-07-28
> **来源**：P0 官方规则书 + P2 `ocg-rulebook.rtfd.io`
> **对应项目**：`pre_state.self_state.field` / `opponent_state.field` 结构、`column_index` 规则

---

### 1. 决斗场地总览

游戏王 OCG 的决斗场地（Field）由双方各半组成。每方有以下区域：

```
┌─────────────────────────────────────────────────────┐
│  [对方场地区]           [对方EX区]  [对方EX区]         │
│  [s5][s4][s3][s2][s1]   对方魔法&陷阱区 (5个)         │
│  [m5][m4][m3][m2][m1]   对方主怪兽区 (5个)            │
├─────────────────────────────────────────────────────┤
│  [m1][m2][m3][m4][m5]   我方主怪兽区 (5个)            │
│  [s1][s2][s3][s4][s5]   我方魔法&陷阱区 (5个)         │
│  [我方场地区]           [我方EX区]  [我方EX区]         │
│  我方卡组  我方额外卡组  我方墓地  我方除外区           │
└─────────────────────────────────────────────────────┘
```

> "场上的卡"（`field`）指放在主怪兽区、EX 怪兽区、魔陷区、场地区、P 区域的卡片。
> 手牌、卡组、额外卡组、墓地、除外区**不算场上的卡**。

---

### 2. 区域详解

#### 2.1 主怪兽区域（Main Monster Zone）

- 数量：**5 个**（m1 ~ m5）
- 用途：放置怪兽卡（通常召唤、特殊召唤、盖放）
- 空位：没有怪兽时用 `"card": null` 表示
- 限制：每方最多同时 5 只怪兽在场

#### 2.2 魔法&陷阱区域（Spell & Trap Zone）

- 数量：**5 个**（s1 ~ s5）
- 用途：发动或盖放魔法卡、陷阱卡
- 特殊：最左（s1）和最右（s5）同时也是**灵摆区域（Pendulum Zone）**——当灵摆怪兽作为魔法卡发动时放置在此
- 限制：每方最多同时 5 张魔陷（包括盖放的和表侧表示的）

#### 2.3 场地区域（Field Spell Zone）

- 数量：**1 个**（每方）
- 用途：放置场地魔法卡
- **不计入**魔陷区的 5 张限制
- 空位：用 `null` 表示

#### 2.4 EX 怪兽区域（Extra Monster Zone）

- 数量：**2 个**（emz_left, emz_right），双方共享
- 用途：从 EX 卡组特殊召唤连接怪兽和表侧灵摆怪兽（必须放这里或连接端指向的主怪兽区）
- 规则：每方最多使用 1 个 EX 区（特殊效果例外）；融合/S/X 怪兽可以自由选择放 EX 区或主怪兽区
- 空位：`column_index` 为 `null`

---

### 3. 纵列（Column）规则

#### 3.1 基本概念

**纵列**是贯穿双方场地的一条垂直线。共 5 个纵列：

```
纵列 1：self.m1 + self.s1 ←→ opp.s5 + opp.m5
纵列 2：self.m2 + self.s2 ←→ opp.s4 + opp.m4
纵列 3：self.m3 + self.s3 ←→ opp.s3 + opp.m3
纵列 4：self.m4 + self.s4 ←→ opp.s2 + opp.m2
纵列 5：self.m5 + self.s5 ←→ opp.s1 + opp.m1
```

#### 3.2 column_index 规则（本项目核心约定）

本项目 Schema 中，`column_index` 以**我方视角**为基准：

```
self:   m1/s1=1, m2/s2=2, m3/s3=3, m4/s4=4, m5/s5=5
opp:    m1/s1=5, m2/s2=4, m3/s3=3, m4/s4=2, m5/s5=1
```

> **关键**：判断同纵列时，只需比较 `self.column_index == opp.column_index`。Workflow 不应再做 `opp_m_i → self_m_(6-i)` 手动换算。

#### 3.3 本项目校验规则

`check_jsonlschema.py` 中的 `_validate_column_mapping` 方法会自动校验双方纵列映射是否正确：

```python
# self:  → [1, 2, 3, 4, 5]
# opponent: → [5, 4, 3, 2, 1]
```

### 5. 区域的规则约束（裁定相关）

#### 5.1 区域不可用（zone_availability）

当效果或规则要求特殊召唤但对应区域满时，操作不合法。例如：
- 主怪兽区 5 只全满 → 不能通常召唤
- 魔陷区 5 张全满 → 不能发动新的魔法/陷阱卡
- 连接怪兽只能出在 EX 区或连接端，对应位置被占时可能无法连接召唤

> **case_046**：灵摆召唤因通道限制 + 区域冲突被判定为 `illegal / zone_availability`

#### 5.2 同纵列效果

部分卡（如"无限泡影"）影响同纵列的其他卡。本项目在 `known_constraints` 中以以下方式建模：

```json
{
  "type": "same_column_spell_trap_negation",
  "source_card": "无限泡影",
  "source_zone": "self.field.spell_trap_zones.s4",
  "affected_column_index": 4,
  "duration": "until_end_of_turn"
}
```

> **case_002** 的核心问题：泡影的同纵列无效效果，在对象卡因连锁处理离场后是否仍适用。

#### 5.3 灵摆区域与魔陷区的重叠

s1 和 s5 同时是灵摆区域。当作魔法卡发动的灵摆怪兽占用该位置，计入魔陷区 5 张限制。

#### 5.4 陷阱怪兽与区域释放（2020 规则）

永续陷阱卡发动后特殊召唤到怪兽区域的场合，原来的魔陷区域**被释放**，可以放置新的卡。这改变了旧规则中陷阱怪兽"锁死"一个魔陷区的行为。

## 03 — 回合结构与阶段/步骤

*（源：`docs/llmstudy/03-turn-structure.md`）*

> **撰写日期**：2026-07-28
> **来源**：P0 官方规则书 + P2 `ocg-rule` 战斗阶段流程文档
> **对应项目**：`pre_state.phase` / `step` / `damage_step_timing` 字段

---

### 1. 回合流程总览

一回合由 **6 个阶段** 组成，回合玩家依次进行：

```
Draw Phase (抽卡阶段)
  ↓
Standby Phase (准备阶段)
  ↓
Main Phase 1 (主要阶段 1)
  ↓
Battle Phase (战斗阶段) ← 先攻第一回合不能进行
  ↓  ├── Start Step (开始步骤)
  │   ├── Battle Step (战斗步骤) ←→ Damage Step (伤害步骤)
  │   └── End Step (结束步骤)
  ↓
Main Phase 2 (主要阶段 2)
  ↓
End Phase (结束阶段)
```

> 每个阶段/步骤的结束需要**双方玩家互相放弃优先权**，且所有效果处理完毕。

---

### 2. 各阶段详解

#### 2.1 抽卡阶段（Draw Phase）

- 回合玩家从卡组抽 1 张卡
- 先攻第一回合**不抽卡**
- 抽卡后，陷阱卡和速攻魔法可以在进入准备阶段前发动

#### 2.2 准备阶段（Standby Phase）

- 处理"准备阶段时发动/适用"的效果（如某些维持 cost）
- 没有此类效果时，双方可发动速攻魔法/陷阱

#### 2.3 主要阶段 1（Main Phase 1）

- **回合玩家可以进行的操作**：
  - 通常召唤 1 只怪兽（每回合限 1 次）
  - 特殊召唤（无次数限制）
  - 盖放魔法/陷阱卡
  - 发动魔法卡（咒文速度 1）
  - 发动怪兽的起动效果（咒文速度 1）
  - 改变怪兽的表示形式
- 其他玩家只能发动速攻魔法/陷阱/怪兽的诱发即时效果（咒文速度 2+）

#### 2.4 战斗阶段（Battle Phase）

**先攻第一回合不能进行。** 如果进行了战斗阶段，结束后才能进入主要阶段 2。

战斗阶段内部细分为 4 个步骤 → 见第 3 节。

#### 2.5 主要阶段 2（Main Phase 2）

- 和主要阶段 1 相同
- 但如果主要阶段 1 已经进行过通常召唤，主要阶段 2 不能再通常召唤（每回合共 1 次）
- 如果没进行战斗阶段，则不能进入主要阶段 2

#### 2.6 结束阶段（End Phase）

- 处理"结束阶段时"发动的效果
- 手牌超过 6 张的场合，舍弃到 6 张
- "直到回合结束时"持续适用的效果在这里终止

---

### 3. 战斗阶段详解

#### 3.1 开始步骤（Start Step）

- 宣言进入战斗阶段
- 处理"战斗阶段开始时"发动的效果

#### 3.2 战斗步骤（Battle Step）

- **攻击宣言**：选择自己场上 1 只表侧攻击表示的怪兽
  - 对方场上有怪兽 → 选择攻击对象
  - 对方场上无怪兽 → 直接攻击对方玩家
- 攻击宣言后，处理"攻击宣言时"和"成为攻击对象时"的效果
- **战斗步骤的卷回**：对方场上怪兽数量变化时，可以重新选择攻击对象或取消攻击
- 1 只怪兽每回合只能攻击 1 次

#### 3.3 伤害步骤（Damage Step）

> **游戏中最复杂的规则区域**。伤害步骤内可发动的效果受到严格限制。

伤害步骤分为 **5 个子时点**：

| 子时点 | 可发动的效果 | 对应 Schema 枚举 |
|---|---|---|
| **伤害步骤开始时** | "伤害步骤开始时"的效果、"不进行伤害计算"的效果 | `start_of_damage_step` |
| **伤害计算前** | 攻守增减效果、里侧怪兽反转（不触发反转效果） | `before_damage_calculation` |
| **伤害计算时** | "伤害计算时"的效果、攻守变化（最终确定值） | `during_damage_calculation` |
| **伤害计算后** | "给与战斗伤害时"、"反转时"的效果 | `after_damage_calculation` |
| **伤害步骤结束时** | 战斗破坏的怪兽送墓、"被战斗破坏时"的效果 | `end_of_damage_step` |

##### 伤害步骤的发动限制

在伤害步骤中，**原则上只能发动以下效果**：
- 反击陷阱（咒文速度 3）
- 使卡片/效果发动无效的效果
- 增减攻击力/守备力的效果（限伤害计算前）
- 自身反转/特殊召唤成功/被破坏/除外等诱发的效果
- 必发效果

> **不能发动**：普通的魔法卡、通常陷阱（除非满足上述条件）、大部分怪兽的起动效果
> 如"灰流丽"等诱发即时效果在伤害步骤中**不能发动**。

## 04 — 连锁系统（Chain）

*（源：`docs/llmstudy/04-chain-system.md`）*

> **撰写日期**：2026-07-28
> **来源**：P0 官方规则书 (SD_RuleBook_EN_10.pdf) + P1 yugipedia + P2 ocg-rule
> **对应项目**：`pre_state.chain_state`、`current_chain_links`、`resolution_history` 字段

---

### 1. 什么是连锁（Chain）

连锁是处理多个卡片效果发动的**顺序机制**。当一方发动效果后，对方总是有机会用另一个效果来响应（"连锁"），形成一个 Chain。

**核心原则**：
- 每次有人发动效果，就形成一个"连锁块"（Chain Link）
- 双方轮流决定是否要追加发动效果
- 当双方都放弃追加时，连锁构建完成
- 然后**逆序处理**（最后发动的先处理）

---

### 2. 咒文速度（Spell Speed）

每个效果都有一个咒文速度（1-3），决定它能否响应其他效果：

| 速度 | 类型 | 能否连锁 | 能被谁连锁 |
|---|---|---|---|
| **1** | 通常魔法、装备魔法、场地魔法、永续魔法、仪式魔法、怪兽的起动/诱发/反转效果 | 不能主动连锁其他效果 | 速度 2 或 3 |
| **2** | 速攻魔法、通常陷阱、永续陷阱、怪兽的诱发即时效果（Quick Effect） | 可以连锁速度 1 或 2 | 速度 2 或 3 |
| **3** | 反击陷阱 | 可以连锁任何速度 | **只有**速度 3 |

> **核心限制**：只能连锁**等于或高于**前一个效果的咒文速度。速度 1 的效果只能是 Chain Link 1（除非多个速度 1 效果同时触发）。

---

### 3. 连锁的构建与处理

#### 3.1 构建阶段（Chain Building）

```
C1: 玩家 A 发动"增援"（通常魔法，Spell Speed 1）
  ↓ 询问玩家 B：是否连锁？
C2: 玩家 B 发动"灰流丽"（诱发即时效果，Spell Speed 2）
  ↓ 询问玩家 A：是否连锁？
  （玩家 A 放弃）
  ↓ 询问玩家 B：是否继续？
  （玩家 B 放弃）
连锁构建完成 ← is_chain_building: false
```

#### 3.2 逆顺处理（Chain Resolving）

构建完成后，从**最后一个连锁块开始向前处理**：

```
C2 先处理：灰流丽的效果→无效 C1 增援的效果
C1 后处理：增援被无效，效果不适用
```

> **关键概念**：处理 C2 时 C1 还没处理——卡片仍在场上。如果 C2 破坏了 C1 的卡，C1 处理时卡已不在场上（这会产生裁定问题，如 case_002）。

---

### 4. 同时触发的效果（SEGOC）

当多个诱发效果在同一时点满足条件时，按以下顺序组成连锁：

1. **回合玩家的必发效果**（任意顺序）
2. **非回合玩家的必发效果**（任意顺序）
3. **回合玩家的选发效果**（任意顺序）
4. **非回合玩家的选发效果**（任意顺序）

> 这就是"自排连锁"（SEGOC: Simultaneous Effects Go On Chain）。
> **case_010** 涉及公开手牌中露世的诱发效果与场上篝的诱发效果——是否仍适用自排连锁规则。

---

### 5. 快速效果时机（Fast Effect Timing）

非回合玩家也能在对方回合发动效果，但必须遵循**快速效果时机表**：

| 游戏状态 | 谁有优先权 | 可进行的操作 |
|---|---|---|
| **开放状态（Box A）** | 回合玩家 | 任何合法操作（通常召唤、发动速度 1 效果等） |
| **不启动连锁的动作后（Box B）** | 回合玩家 | 只能发动快速效果（速度 2+） |
| **回合玩家放弃后（Box C）** | 非回合玩家 | 快速效果 |
| **连锁构建中（Box D）** | 最后一个发动者的对方 | 追加连锁 |
| **阶段转换前（Box E）** | 非回合玩家 | 快速效果 |

#### 关键规则

- **通常召唤后**：触发效果（如有）先组成连锁（黄框）→ 然后才轮到快速效果（B/C 框）
- **连锁处理完后**：游戏状态**不是开放状态**——先检查触发效果（黄框），然后双方轮流获得快速效果机会
- 只有在连锁完全处理完 + 没有新连锁 + 双方都放弃快速效果后，游戏状态才回到"开放"

---

### 6. 本项目的连锁表示

#### 6.1 连锁编号

所有连锁编号统一使用大写 C 加数字：
```
C1, C2, C3, ...
```

禁用旧写法 `chain_link: 1`（v2.0.0 已废弃）。

#### 6.2 连锁状态（chain_state）

```json
{
  "chain_state": {
    "is_chain_building": true,     // 正在构建连锁（还能追加）
    "is_chain_resolving": false,    // 不是正在逆顺处理
    "current_chain_links": [        // 当前连锁上的所有连锁块
      {
        "chain_id": "C1",
        "player": "opponent",
        "card": "闪刀启动：交闪",
        "operation_type": "activate_card",
        "effect_id": "main_effect",
        "effect_summary": "从卡组把一张「闪刀」卡加入手卡",
        "effect_features": ["add_from_deck_to_hand"],
        "activation_start_location": "hand",
        "activation_location": "spell_trap_zone",
        "activation_zone": "s3",
        "activation_column_index": 3
      }
    ]
  }
}
```

#### 6.3 关键字段对应

| 字段 | 用途 | 示例 |
|---|---|---|
| `chain_id` | 连锁块的编号 | `"C1"` |
| `chain_response_to` | 表示本发动响应的连锁块 | `"C1"`（表明是 C2 连锁 C1） |
| `chain_id_to_resolve` | 当前要处理的连锁块 | `"C1"`（用于 resolve_effect 操作类型） |
| `resolved_chain_id` | 已经处理完成的连锁块 | `"C3"`（用于 resolution_history） |
| `current_chain_id` | 场上卡关联的当前连锁块 | `"C2"`（表明此卡在 C2 上发动） |

#### 6.4 校验规则

`check_jsonlschema.py` 对连锁有以下校验：
- 所有 `chain_id` 必须在当前 case 内唯一
- `chain_response_to` 和 `chain_id_to_resolve` 必须引用 `current_chain_links` 中真实存在的连锁块
- `resolution_history` 中的 `resolved_chain_id` 必须引用当前连锁上下文中的 ID

---

### 7. 连锁相关裁定案例

| 场景 | 对应 case | 核心裁定点 |
|---|---|---|
| 灰流丽连锁增援 | case_001 | 诱发即时效果可以在对方回合发动，连锁速度 2 对速度 1 |
| 超融合不能被连锁 | case_012 | 卡的效果文本"不能对应这张卡的发动把卡的效果发动"→ 直接连锁不合法 |
| C1 魔法被 C3 炸掉后 C2 泡影是否还影响 | case_002 | 同纵列无效效果在对象卡离场后是否仍适用 |
| 整条连锁处理后另开触发 | case_031 | 卢恩神碑之泉的诱发时机 |
| "不能对应发动连锁"只限制直接连锁 | case_032 | C2 不能回应，但 C3 可以回应 C2… |

---

### 8. resolution_history（已处理连锁历史）

`resolution_history` 是 `pre_state` 的**必填字段**，记录当前判断时点之前已经处理完成的连锁结果：

```json
{
  "resolution_history": [
    {
      "resolved_chain_id": "C3",
      "card": "落胤与圣女",
      "result": [
        {
          "action": "destroy",
          "card": "烙印之气炎",
          "from": "opponent.field.spell_trap_zones.s2",
          "to": "opponent.graveyard"
        }
      ]
    }
  ]
}
```

#### 关键规则

1. **只记录已处理完成的连锁块**，不记录将要处理的内容
2. **顺序按实际处理时间**：连锁逆顺处理中高编号先处理（`C3 → C2 → C1`）
3. **空数组 `[]` 是有意义的**：表示"当前判断点前没有已处理连锁块"，不是缺失信息
4. **result 必须是非空数组**：没有结构化结果的不要写 history item
5. **持续限制写入 `known_constraints`**，不要写入 `resolution_history`

> 在 `effect_resolution_judgment` 类 case 中，`resolution_history` 帮助判断"已经处理完成的结果对当前待处理效果的影响"——这是效果处理合法性判断的核心依赖。

## 05 — 召唤机制全类

*（源：`docs/llmstudy/05-summon-mechanics.md`）*

> **撰写日期**：2026-07-28
> **来源**：P0 官方规则书 + P2 `ocg-rule` / `ocg-rulebook`
> **对应项目**：`operation_type` 中与召唤相关的枚举，58 条 case 中涉及的召唤裁定

---

### 1. 召唤的分类

游戏王中的怪兽出场方式分为三大类：

```
怪兽出场方式
├── 通常召唤 (Normal Summon)
│   ├── 召唤 (表侧攻击表示) — 每回合 1 次
│   ├── 盖放 (里侧守备表示) — 每回合 1 次（和召唤共享次数）
│   └── 上级召唤 (Tribute Summon) — LV5+ 需要解放怪兽
├── 反转召唤 (Flip Summon) — 不限次数
└── 特殊召唤 (Special Summon) — 不限次数（除灵摆召唤外）
    ├── 不入连锁 (条件特殊召唤)
    │   ├── 同调召唤 / 超量召唤 / 连接召唤
    │   ├── 灵摆召唤 (每回合 1 次)
    │   └── 怪兽自身记载的特殊召唤手续
    └── 入连锁 (发动效果特殊召唤)
        ├── 融合召唤 (通过"融合"等效果)
        ├── 仪式召唤 (通过仪式魔法)
        └── 各种效果特殊召唤
```

---

### 2. 通常召唤（Normal Summon）

#### 2.1 基本规则

- **每回合 1 次**：每个玩家每回合只能进行 1 次通常召唤
- **只能在主要阶段**进行
- **需要可用的主怪兽区域**
- **表示形式**：表侧攻击（召唤）或里侧守备（盖放）

#### 2.2 上级召唤（Advance Summon）

等级 5-6 的怪兽需要解放自己场上 **1 只**怪兽。
等级 7+ 的怪兽需要解放自己场上 **2 只**怪兽。

> 解放（Tribute）是 cost，不进入连锁。

#### 2.3 通常召唤的限制与裁定

- 被「神之宣告」无效的通常召唤**不计入**本回合的通常召唤次数（2020.04 规则修订）
- 「召唤限制」等持续效果可以限制通常召唤次数
- 「血之代偿」等效果可以在对方回合进行通常召唤

> 本项目 `operation_type` 枚举包含 `normal_summon` 和 `set_monster`。case_051（被神之宣告无效的通常召唤不计入次数）覆盖 `normal_summon`，case_053（暗黑神鸟限制下不能盖放怪兽）覆盖 `set_monster`。

---

### 3. 特殊召唤（Special Summon）

#### 3.1 不入连锁的特殊召唤（条件特殊召唤）

| 召唤类型 | 说明 | 素材要求 | 出场区域限制 |
|---|---|---|---|
| **同调召唤** | 调整 + 非调整，等级合 = 同调怪兽等级 | 从场上送墓 | EX 区或主怪兽区 |
| **超量召唤** | 同等级怪兽叠放（素材不送墓） | 场上同等级怪兽 | EX 区或主怪兽区 |
| **灵摆召唤** | 手牌 + 表侧额外卡组的灵摆怪兽 | 灵摆刻度之间的等级 | 主怪兽区（额外组的需 EX 区或连接端） |
| **连接召唤** | 素材数 = LINK 值 | 从场上送墓 | EX 区或连接端的主怪兽区 |
| **召唤手续** | 怪兽自身记载的条件 | 各卡不同 | 主怪兽区 |

> 不入连锁 = 没有效果发动，因此在召唤成功前不能被连锁（但召唤可以被"神之宣告"等无效召唤的效果无效）。

#### 3.2 入连锁的特殊召唤（效果特殊召唤）

- 融合召唤、仪式召唤属于此类（通过发动魔法卡的效果）
- 各种怪兽效果、魔法陷阱效果的特殊召唤
- 由于在效果处理中进行特殊召唤，**效果处理途中不能插入"神之宣告"**
- 效果处理完毕后 → 特殊召唤成功时 → 可以发动"激流葬"等

#### 3.3 关键区分：效果特召 vs 召唤手续

**"进行连接召唤的效果" ≠ "效果特殊召唤"**

这是本项目 case_005 的核心裁定点。例如：

- **I:P 伪装舞会莱娜**的效果："以包含此卡在内的自己场上怪兽作为素材进行连接召唤"
  - 这是"让玩家在效果处理后进行连接召唤"的效果
  - 连接召唤本身是不入连锁的召唤手续，不是"因发动的效果特殊召唤"
  - 因此结果怪兽**不视为被怪兽效果特殊召唤**

> 本项目用三个 `effect_features` 精确表达此语义：`perform_link_summon_after_chain_link_resolution` + `includes_special_summon_effect` + `resulting_monster_not_summoned_by_activated_effect`

---

### 4. 苏生限制（Rebirth Restriction）

#### 4.1 核心规则

**特殊召唤怪兽必须先用正规手续出场一次**，之后才能被"死者苏生"等效果从墓地/除外区特殊召唤。

- 融合/S/X/连接怪兽：正规手续 = 对应召唤方式
- 没满足正规手续就被直接送墓的怪兽 → 不能用效果苏生
- 正规出场后加入卡组/手牌等非公开场所 → 失去正规出场履历

#### 4.2 召唤限制

部分怪兽有额外限制，如「青眼混沌龙」：

> "不用仪式召唤不能特殊召唤"

这类怪兽即使正规出场过，也不能被"死者苏生"等效果特殊召唤。

#### 4.3 无视召唤条件

「无视召唤条件特殊召唤」的效果可以绕过上述两类限制——但前提是怪兽没有类似的永续限制文本。

> **case_036** 涉及"无视召唤条件仍要求特殊召唤怪兽正规出场履历"，这是苏生限制的典型场景。

---

### 5. 盖放（Set）

#### 5.1 怪兽盖放

- 里侧守备表示放置到主怪兽区
- 计入每回合 1 次的通常召唤次数
- 盖放的怪兽在下回合可以反转召唤

#### 5.2 魔法/陷阱盖放

- 放置在魔陷区（不计入通常召唤次数）
- 盖放的魔法卡（除速攻魔法）盖放回合不能发动
- 盖放的陷阱卡盖放回合不能发动
- 盖放的速攻魔法盖放回合不能发动

> 本项目 `operation_type` 包含 `set_card` 枚举值，用于表示"盖放魔法/陷阱卡"的操作。

---

### 6. 与本项目的关联

#### 召唤相关的 operation_type

## 06 — Cost、效果、处理

*（源：`docs/llmstudy/06-cost-effect-resolution.md`）*

> **撰写日期**：2026-07-28
> **来源**：P0 官方规则书 + P2 `ocg-rule`
> **对应项目**：`declared_cost`、`resolution_history`、`attempted_operation` 中的 cost 和效果处理相关字段

---

### 1. Cost（代价）的概念

Cost 是发动卡片或效果时必须**先支付**的代价。关键特性：

- **在效果处理之前支付**（发动时立即支付）
- **不能撤回**：即使效果被无效，cost 也不退还
- **不是效果**：cost 不能被效果无效
- **不进入连锁**：cost 支付本身不能被连锁

#### 1.1 Cost 的支付流程

```
发动宣言 → 支付 cost → 选择对象（如需要）→ 双方确认 → 效果进入连锁
```

> 如果 cost 无法支付，**不能发动**该效果。这就是 `failed_check = "cost_payability"` 的场景。

---

### 2. 本项目的 Cost 枚举

Schema 中 `declared_cost.type` 固定为四种：

| cost 类型 | 附加必填字段 | 说明 | 对应 case |
|---|---|---|---|
| `discard` | `card` | 从手牌舍弃 | case_001 (灰流丽舍弃自身) |
| `pay_lp` | `amount`（正整数） | 支付 LP | — |
| `banish` | `card`, `from` | 除外 | — |
| `send_to_graveyard` | `card`, `from` | 送墓 | case_024 (灵摆怪兽不能送墓) |

#### 2.1 Cost 相关裁定案例

| 场景 | case | 裁定 |
|---|---|---|
| 灰流丽舍弃自身为 cost | case_001 | 合法，cost 先支付 |
| 宏观宇宙下不能以送墓为 cost | case_013 | `cost_payability` — 卡被除外而不是送墓 |
| 灵摆怪兽不能送墓为 cost | case_024 | 场上灵摆怪兽送墓时改为表侧加额外卡组 |

---

### 3. 效果（Effect）的分类

#### 3.1 怪兽效果的 5 种分类

| 分类 | 咒文速度 | 入连锁 | 说明 | 典型卡片 |
|---|---|---|---|---|
| **起动效果** | 1 | 是 | 自己主要阶段主动发动 | 救援兔 |
| **诱发效果** | 1 | 是 | 满足条件时发动 | 元素英雄 天空侠 |
| **诱发即时效果** | 2 | 是 | 对方回合也能发动 | 灰流丽、效果遮蒙者 |
| **永续效果** | — | 否 | 只要在场就持续适用 | 技能抽取、王家长眠之谷 |
| **无种类效果** | — | 否 | 规则文本、召唤手续等 | "这张卡不能通常召唤" |

#### 3.2 魔法/陷阱卡的效果

魔法陷阱卡没有上述怪兽效果的分类体系，但类似的效果也存在：
- **永续魔法/陷阱**：类似永续效果，持续适用
- **诱发类效果**：魔法陷阱卡被送墓时发动的效果（如"技能抽取"的①效果不适用）

---

### 4. "发动" vs "适用" vs "处理"

#### 4.1 发动（Activate）

- 卡的发动：把魔法/陷阱卡从手牌放到场上、或把盖放的卡翻开
- 效果的发动：宣言使用某个效果

> 被"魔宫的贿赂"等无效的是**发动**，整个连锁块不存在。
> 被"灰流丽"等无效的是**效果**，发动本身有效但效果不适用。

#### 4.2 适用（Apply）

- 永续效果不"发动"，直接"适用"
- "得到以下效果"、"当作……使用"等也是适用

#### 4.3 处理（Resolve）

- 效果处理是连锁逆顺处理中执行效果内容的过程
- 效果处理中可能出现"不适用"的情况（如对象不合法）

---

### 5. 本项目的效果处理表示

#### 5.1 resolution_history 的 action 枚举

| action | 说明 |
|---|---|
| `destroy` | 破坏 |
| `banish` | 除外 |
| `special_summon` | 特殊召唤 |
| `send_to_graveyard` | 送墓 |
| `return_to_hand` | 回手牌 |
| `return_to_extra_deck` | 回额外卡组 |
| `return_to_field` | 回场上 |
| `negate_monster_effects_until_end_of_turn` | 无效怪兽效果至回合结束 |
| `negate_effects_and_halve_atk` | 无效效果并攻击力减半 |
| `apply_same_column_spell_trap_negation` | 适用同纵列魔陷无效 |
| `change_to_face_down_defense` | 变成里侧守备表示 |
| `redirect_battle_damage` | 转嫁战斗伤害 |
| `apply_attack_decrease_and_restrictions` | 适用攻击力降低和限制 |

#### 5.2 effect_features

`effect_features` 是机器可读的效果特征枚举，用于标记一个效果的关键特性：

```json
"effect_features": [
  "add_from_deck_to_hand",   // 从卡组检索
  "discard_revealed_monster" // 舍弃已展示的怪兽
]
```

当前 Schema 中有 56 个 feature，58 条 case 中实际使用了 32 个。

---

### 6. 效果处理的重要规则

#### 6.1 效果处理中的场所移动

- 效果处理中，卡片从发动场所移动到其他场所 → 效果可能不适用
- 2020.04 规则：诱发效果在发动前场所移动 → 不发动

#### 6.2 效果处理中不能插入其他效果

- 一个效果正在处理时，不能发动别的效果
- 例：融合召唤在处理中 → 不能插入神之宣告无效融合召唤

#### 6.3 效果处理中的"尽可能"规则

- "尽可能适用"：能适用的部分就适用
- "才能发动"：必须全部条件满足才适用

#### 6.4 离场后的效果处理

卡片离场后，部分效果仍然适用（取决于效果文本）。
> **case_002** 的核心问题：烙印之气炎因连锁被破坏送墓后，无限泡影的同纵列无效效果是否仍然影响它。

## 07 — 取对象（Targeting）规则

*（源：`docs/llmstudy/07-targeting.md`）*

> **撰写日期**：2026-07-28
> **来源**：P0 官方规则书 + P2 `ocg-rule`
> **对应项目**：`declared_targets` 字段、`target_legality` 的 failed_check

---

### 1. 什么算"取对象"

**取对象（Targeting）** 是指效果在发动时选择特定的卡作为效果的处理目标。

#### 1.1 如何判断是否取对象

日文原文判断方法——看效果文本：

| 文本特征 | 是否取对象 |
|---|---|
| 「○○を対象として発動できる」（以○○为对象才能发动） | **是** |
| 「○○を対象とする」（以○○为对象） | **是** |
| 「選ぶ」（选择） | **通常不取对象** |
| 没有上述字样 | 一般不取对象 |

> 简中官方文本同样遵循此规则——"以……为对象"就是取对象，"选……"不取对象。

#### 1.2 取对象 vs 不取对象

| | 取对象 | 不取对象（处理时选择） |
|---|---|---|
| 选择时机 | **发动时** | **效果处理时** |
| 对方能否在连锁中确认 | 是（公开信息） | 否（处理时才决定） |
| 不被取对象的效果能避免吗 | 能 | 不能 |
| 适用前对象消失的处理 | 效果不适用 | 处理时才选，不存在消失问题 |

---

### 2. 取对象的时间线

#### 2.1 发动时取对象（标准流程）

```
1. 宣言发动
2. 支付 cost
3. 选择对象（此时对方看到选择了什么）
4. 确认连锁
5. 效果处理：检查对象是否仍然合法
6. 如合法 → 处理效果
   如不合法 → 效果不适用（"不発"）
```

#### 2.2 对象的连续性

对象一旦被选定，效果处理时会再次检查对象是否合法：
- 对象变成里侧 → 取决于效果文本是否要求表侧
- 对象离开场上 → 通常效果不适用
- 对象从怪兽区域移到魔陷区域 → 不再是"场上的怪兽"

> **case_025**：墓穴指名者的对象在效果处理时离开墓地 → `target_legality` 不合法

---

### 3. 本项目的 target 表示

```json
{
  "card": "原始生命态 尼比鲁",
  "controller": "opponent",
  "location": "monster_zone",
  "zone": "m3",
  "status": "face_up",
  "card_type": "monster",
  "monster_type": "effect",
  "column_index": 3
}
```

`declared_targets` 是 `attempted_operation` 中的可选数组，用于记录发动时声明的对象。

---

### 4. 不取对象的"选择"效果

部分效果文本使用「選ぶ」（选择）而非「対象」：

例如：「地帝 格兰玛格」—— "把场上盖放的 1 张卡破坏"
- 效果处理时才选择哪张卡
- 对方不能在连锁中通过移除潜在目标来保护
- 不受取对象抗性影响

本项目 Schema 中用两个 effect_features 区分：
- `destroy_target` — 发动时取对象并破坏
- `choose_1_card_on_field_on_resolution` + `destroy_chosen_card` — 处理时选择并破坏

## 08 — 一回合一次与次数限制

*（源：`docs/llmstudy/08-once-per-turn.md`）*

> **撰写日期**：2026-07-28
> **来源**：P1 yugipedia / YGOrg + P2 `ocg-rule`
> **对应项目**：`failed_check: once_per_turn`、`known_constraints` 中的 `once_per_turn_used`、case_007/037

---

### 1. 三种限制级别

游戏王中"一回合一次"的表述有三种，限制严格程度递增：

| 级别 | 日文表述 | 中文表述 | 限制范围 |
|---|---|---|---|
| **软限制 (Soft OPT)** | 「１ターンに１度」 | "1 回合 1 次" | 每张卡各自独立 |
| **硬限制 (Hard OPT)** | 「このカード名の効果は１ターンに１度しか使用できない」 | "此卡名的效果 1 回合仅可使用 1 次" | 同名卡共用 |
| **单效果限制** | 「このカード名の効果は１ターンに１度、いずれか１つしか使用できない」 | "此卡名的效果 1 回合仅能选择 1 个使用 1 次" | 同名卡 + 多选一 |

---

### 2. 软限制（Soft Once Per Turn）

#### 2.1 规则

- **每张卡独立**：场上 2 张同名的"1 回合 1 次"卡可以各自发动 1 次
- **状态重置**：卡离开场上再回来、或变成里侧再翻开，限制重置
- **即使发动/效果被无效**，也视为已使用
- **被盖放再翻开**：视为"新的卡"，可以再次发动

> **case_007 的核心**：冰剑龙②效果是"此卡名的此效果 1 回合仅可使用 1 次"（硬限制）。冰剑龙被盖放后效果是否重置？

#### 2.2 状态重置的边界

什么会重置软限制？

| 情况 | 是否重置 |
|---|---|
| 卡被盖放（变成里侧）再翻开 | 是 — 视为新的卡 |
| 卡离场再回到场上 | 是 |
| 卡的控制权转移 | 否（还是同一张卡） |
| 卡从怪兽区移到魔陷区再回来 | 是（除非是陷阱怪兽） |

---

### 3. 硬限制（Hard Once Per Turn — HOPT）

#### 3.1 规则

- **同名卡全局共用**：不管场上有几张同名卡，总共只能使用 1 次
- 从手牌发动、墓地发动、场上发动——**全部计入同一限制**
- 即使卡名被改变，限制仍然基于**原本卡名**

#### 3.2 发动 vs 效果 vs 适用

日文用词不同，限制严格程度也不同：

| 日文术语 | 含义 | 被发动无效后能否再发 |
|---|---|---|
| **使用（使用）できない** | 不能使用 | **不能**（最严格） |
| **发动（発動）できない** | 不能发动 | **能**（发动被无效 = 没发动过） |
| **适用（適用）できない** | 不能适用 | **能**（最宽松） |

> 大多数现代怪兽效果使用"使用できない"，因此即使发动被"神之宣告"无效，该卡同名效果的"1 回合 1 次"仍然消耗。

#### 3.3 硬限制的案例

| 场景 | case | 裁定 |
|---|---|---|
| 冰剑龙盖放后效果是否重置 | case_007 | `once_per_turn` — **不重置**：硬限制基于卡名，盖放不改变卡名 |
| 冰剑龙里侧被翻开后还能发动吗 | case_007 | 冰剑龙②效果是硬限制 → 不能 |
| ●项目被无效仍算已选择 | case_037 | `once_per_turn` — 无效不重置选项 |

---

### 4. 单效果限制（Only 1 Effect Once Per Turn）

#### 4.1 规则

最严格的限制类型：

> "此卡名的效果 1 回合仅能选择 1 个使用 1 次"

- 同名卡全局只能使用 1 个效果（总共 1 次）
- 如果卡有多个●效果，只能用其中一个
- **case_037** 涉及此类："一回合一次的●项目被无效仍算已选择"

---

### 5. 同名卡发动限制（卡名限一）

部分魔法陷阱卡有：

> "此卡名的卡 1 回合只能发动 1 张"

- 只限制"卡的发动"，不限制"效果的发动"
- **如果发动被无效** → 可以再发动同名卡（因为"发动"本身不存在了）
- 例：「奥义之魔导书」被「魔宫的贿赂」无效 → 可以再发动一张

---

### 6. 其他次数限制

#### 6.1 「XX 1 回合只能有 1 次特殊召唤」

2020.04 规则修订后：被无效的特殊召唤不计入限制。

#### 6.2 召唤次数限制

「召唤限制」（Summon Limit）：每回合双方最多召唤 2 次。被无效的召唤不计入。

#### 6.3 「You can only gain this effect once per turn」

与次数无关的特殊文本——多个带有此文本的追加通常召唤效果，每回合只能选 1 个适用。

---

### 7. 本项目的表示

#### known_constraints 中的 once_per_turn

```json
{
  "type": "once_per_turn_used",
  "card": "冰剑龙 幻冰龙",
  "effect_id": "effect_2",
  "effect_label": "②",
  "description": "冰剑龙②效果本回合已使用"
}
```

> 这捕获了"当前判断时点前已经使用过的效果"，用于判断下一次发动是否违反次数限制。

#### effect_features 中的相关标记

- `select_once_per_turn_option` — 涉及"一回合选择一次"的●项
- `ignition_effect` — 作为起动效果的次数限制判断前提

---

### 8. 汇总：各 case 涉及的次数限制场景

| case | 限制类型 | 裁决 |
|---|---|---|
| case_007 | 硬限制 + 盖放重置 | illegal — HOPT 不因盖放重置 |
| case_037 | 单效果限制 + 无效 | illegal — ●项目被无效仍算已选择 |
| case_011 | 联合机库发动处理中特召 | illegal — 窗口不合法 |
| case_031 | 卢恩神碑之泉整条连锁后触发 | legal — 另开时点不计入限制 |
| case_016 | 米德拉什的召唤限制 | illegal — 包含特召的效果不能发动 |

## 09 — 持续效果 vs 发动效果

*（源：`docs/llmstudy/09-continuous-vs-activated.md`）*

> **撰写日期**：2026-07-28
> **来源**：P2 `ocg-rule` + P1 yugipedia
> **对应项目**：`failed_check: effect_resolution_rule`、case_015/018/045（涉及 Skill Drain/持续效果相关）

---

### 1. 持续效果（Continuous Effect）

#### 1.1 定义

**不入连锁、只要怪兽在场就持续适用**的效果。没有发动时机，不需要宣言。

#### 1.2 典型例子

| 卡片 | 持续效果 | 类型 |
|---|---|---|
| 技能抽取 (Skill Drain) | "场上的表侧表示怪兽的效果无效化" | 陷阱的永续效果类 |
| 王家长眠之谷 (Necrovalley) | "涉及墓地的卡的效果无效化" | 场地的效果 |
| 米德拉什 (El Shaddoll Winda) | "双方 1 回合只能有 1 次特殊召唤" | 怪兽的永续效果 |
| 电子界到临者 (The Arrival Cyberse) | "不受其他卡的效果影响" | 怪兽的永续效果 |

#### 1.3 持续效果的规则特性

- **不发动** → 不能被"魔宫的贿赂"等无效发动的卡连锁
- **只要满足条件就立即适用** → 离场时立即不适用
- **被无效时**（如 Skill Drain 适用中）→ 永续效果不适用
- **适用优先级**：先适用的持续效果先影响场面

---

### 2. "不受效果影响" (Unaffected)

#### 2.1 核心概念

部分怪兽有"不受其他卡的效果影响"的能力。这不等于"不能被取对象"。

| 文本 | 保护范围 | 能否取对象 |
|---|---|---|
| "不受其他卡的效果影响" | 所有效果（取对象+不取对象） | 不能取对象（因为取对象本身是效果的一部分） |
| "不会成为效果的对象" | 仅取对象效果 | 不能取对象，但可以被不取对象的效果影响 |
| "不会被效果破坏" | 仅破坏效果 | 可以取对象，也可以被除外/送墓 |

#### 2.2 Unaffected 怪兽与 Skill Drain

- **已经适用 Skill Drain** → unaffected 怪兽出场 → 谁的效果适用？
  - 新出场的怪兽的效果在后适用 → 不受 Skill Drain 影响
- **Unaffected 怪兽先在场** → Skill Drain 后适用？
  - Skill Drain 不影响它 → 永续效果仍在 → unaffected

> 这是 case_015 的核心：伤害步骤中龙骑兵团的效果不受 Skill Drain 影响。如果 unaffected 怪兽在场，Skill Drain 对它无效。

---

### 3. 持续效果与其他规则的交互

#### 3.1 持续效果 vs 发动效果

"不受其他卡的效果影响"的怪兽：
- 不能成为取对象的发动效果的目标
- 不适用不取对象的发动效果的处理
- **但**仍然受规则约束（不能被效果破坏 ≠ 不能被战斗破坏）

#### 3.2 作用于怪兽 vs 作用于玩家的限制

这是非常重要的区分——直接影响 case_003 的裁定：

| 限制类型 | effect_scope | 特性 |
|---|---|---|
| 作用于怪兽 | `monster` | "不受效果影响"的怪兽可以绕过 |
| 作用于玩家 | `player` | "不受效果影响"不能绕过 |

**case_003 场景**：
- S:P 小夜骑士的效果："自己怪兽不能直接攻击"
- 如果建模为 `effect_scope: "monster"` → 全抗怪兽（不受影响）可以绕过
- 如果建模为 `effect_scope: "player"` → 任何怪兽都不能直接攻击
- **正解**：S:P 的效果是作用于怪兽的 → effect_scope: monster → 全抗怪兽可以直接攻击

#### 3.3 持续适用 vs 已经发动的效果

- Skill Drain 适用中发动的效果：处理时效果无效
- Skill Drain 适用前已成功发动的效果：已经适用的部分不回溯

> **case_018**：颠茄歌后在 Skill Drain 适用中发动效果，处理时效果无效。

---

### 4. 永续魔法/陷阱的效果

#### 4.1 与怪兽永续效果的相似性

永续魔法/陷阱在场时持续适用的效果：
- 卡从场上离开 → 效果立即不适用
- 卡被无效（如"旋风"破坏前适用）→ 效果立即不适用
- "发动"本身可以连锁（因为是卡的发动），但持续适用的部分不发动

#### 4.2 永续陷阱怪兽

陷阱卡发动后变成怪兽特殊召唤：
- 在怪兽区域时：当作怪兽，怪兽相关的效果影响它
- 在魔陷区域时：当作陷阱卡
- 2020.04 规则：变成怪兽后释放原来魔陷区域

---

### 5. 关键裁定案例

| 场景 | case | 核心裁定 |
|---|---|---|
| Skill Drain 下龙骑兵团发动效果 | case_015 | legal — 伤害步骤中适用的效果不受 Skill Drain 影响 |
| Skill Drain 下颠茄歌后的处理 | case_018 | illegal — 持续无效已适用，效果处理无效 |
| S:P 限制下全抗怪兽的直接攻击 | case_003 | legal — 怪兽限定的限制，unaffected 怪兽可绕过 |
| 白龙忍者保护光之护封剑？ | case_045 | legal — 自毁不是"对方的效果"，白龙忍者不保护 |

## 10 — 优先权与发动窗口

*（源：`docs/llmstudy/10-priority-and-window.md`）*

> **撰写日期**：2026-07-28
> **来源**：P0 KONAMI Fast Effect Timing Chart + P2 `ocg-rule`
> **对应项目**：`failed_check: activation_window`、case_006/011/021/022

---

### 1. 优先权（Priority）

#### 1.1 两种优先权

| 类型 | 说明 |
|---|---|
| **发动卡的优先权** | 发动下一个效果的权利——在连锁构建中来回转移 |
| **进行回合的优先权** | 推进阶段/步骤的权利——属于回合玩家 |

#### 1.2 优先权的转移

效果发动时会转移优先权。以下行动**不转移**优先权：
- 通常召唤/盖放
- 不入连锁的特殊召唤
- 改变怪兽表示形式
- 攻击宣言

> **关键**：回合玩家通常召唤后，如果没有诱发效果触发，回合玩家仍然持有优先权，可以发动速度 2 的效果（先于非回合玩家）。

---

### 2. 快速效果时机表（Fast Effect Timing）

游戏状态在以下 6 个框之间流转：

| 框 | 状态 | 谁有优先权 | 可做什么 |
|---|---|---|---|
| **A** | 开放状态 | 回合玩家 | 任何合法操作 |
| **B** | 不启动连锁的动作后（无诱发触发时） | 回合玩家 | 快速效果 |
| **C** | 回合玩家放弃后 | 非回合玩家 | 快速效果 |
| **D** | 连锁构建中 | 最后发动者的对方 | 追加连锁 |
| **E** | 阶段转换前 | 非回合玩家 | 快速效果 |
| **黄框** | 有诱发效果触发 | — | 按 SEGOC 规则组成连锁 |

#### 2.1 典型场景

**场景：通常召唤后发动效果**
```
A: 回合玩家通常召唤"救援兔"
  ↓（不启动连锁的动作）
黄框: 有诱发效果触发吗？→ 没有
B: 回合玩家要发动快速效果吗？→ 不（"救援兔"是速度 1 的起动效果）
C: 非回合玩家要发动快速效果吗？→ 发动"效果遮蒙者"（速度 2）
  ↓
D: 连锁构建 → 逆顺处理
  ↓ 连锁处理完毕
黄框: 有新的诱发效果触发吗？→ 没有
B: 回合玩家要发动快速效果吗？→ 放弃
C: 非回合玩家要放弃吗？→ 放弃
  ↓
A: 回到开放状态。回合玩家可以发动"救援兔"的起动效果
```

---

### 3. 召唤成功窗口（Summon Success Window）

"召唤成功时"有专门的发动窗口：

1. 怪兽通常/特殊召唤成功
2. → 检查诱发效果（黄框）→ 回合玩家/NTP 的诱发效果组成连锁
3. → 处理完后 → 快速效果窗口（B/C 框）

#### 3.1 起动效果 vs 诱发即时效果

- 召唤成功时，**不能**先发动怪兽的起动效果（速度 1）
- 必须先处理诱发效果 → 然后快速效果窗口 → 回到开放状态 → 然后才能发动起动效果

> **case_021**：召唤成功时不能先发动起动效果 → `activation_window` 不合法
> **case_022**：欧贝利斯克召唤成功时封锁一切发动 → `activation_window`

---

### 4. 通常召唤后的优先权争夺

**回合玩家通常召唤 → 没有诱发效果触发 → 谁有优先权发速度 2 效果？**

→ **回合玩家**。

但在实践中常被简化为"非回合玩家可以先发效果遮蒙者"——这是双方默契地跳过了 B/C 框。

> **case_006**：连接召唤成功后，优先权属于回合玩家 → 对方不能抢先发尼比鲁 → `activation_window` 不合法

---

### 5. 阶段转换时的发动机会

宣言进入下个阶段/步骤 = 放弃优先权。非回合玩家可以在阶段转换前发动效果（E 框）。

例如：
- 回合玩家宣言"结束主要阶段"
- → 非回合玩家可以发动速攻魔法（阶段转换前 = 仍在主要阶段）
- → 处理后回到主要阶段
- → 回合玩家可以继续操作（"卷回"到主要阶段）

---

### 6. 激活窗口限制

#### 6.1 只能在主要阶段发动的效果

- 通常魔法（速度 1）
- 怪兽的起动效果（速度 1）
- 通常/上级召唤
- 大多数不入连锁的条件特殊召唤

#### 6.2 可以在任意阶段发动的效果

- 速攻魔法（速度 2）
- 陷阱卡（速度 2-3）
- 怪兽的诱发即时效果（速度 2）

---

### 7. 发动窗口相关裁定案例

| 场景 | case | 裁定 |
|---|---|---|
| 连接召唤后优先权与尼比鲁 | case_006 | illegal — 优先权在回合玩家，尼比鲁不能抢先 |
| 联合机库发动处理中同连锁特召 | case_011 | illegal — 效果处理中的窗口已被关闭 |
| 召唤成功后不能先发动起动效果 | case_021 | illegal — 必须等诱发效果+快速效果窗口 |
| 欧贝利斯克召唤成功封锁发动 | case_022 | illegal — 怪兽效果封锁了窗口 |
| 卢恩神碑之泉另开触发 | case_031 | legal — 连锁处理后另开时点是合法窗口 |

## 11 — 伤害步骤（Damage Step）特殊规则

*（源：`docs/llmstudy/11-damage-step.md`）*

> **撰写日期**：2026-07-28
> **来源**：P0 官方规则书 + P2 `ocg-rule` 战斗阶段流程
> **对应项目**：`damage_step_timing` 枚举、case_015/026/035

---

### 1. 伤害步骤的 5 个子时点

```
伤害步骤开始时 (start_of_damage_step)
  → 伤害计算前    (before_damage_calculation)
    → 伤害计算时  (during_damage_calculation)
      → 伤害计算后 (after_damage_calculation)
        → 伤害步骤结束时 (end_of_damage_step)
```

---

### 2. 各子时点详解

#### 2.1 伤害步骤开始时

- "不进行伤害计算"的效果、"伤害步骤开始时"的诱发效果
- **里侧怪兽还未反转**（反转在伤害计算前）

#### 2.2 伤害计算前

- **里侧怪兽反转成表侧**（不触发反转效果）
- 攻守增减效果（如"禁忌的圣枪"）可以发动
- "伤害计算前"的诱发效果在此组成连锁

#### 2.3 伤害计算时

- **真正的伤害计算发生**
- 攻守变化效果最终确定
- **被战斗破坏的怪兽确定**（但不立即送墓，等到结束时）
- 「伤害计算时」的效果只能在此发动（且必须组成第一条连锁）

#### 2.4 伤害计算后

- "给与对方战斗伤害时"的效果
- "反转时"的效果（反转效果在此发动）
- "伤害计算后"的效果

#### 2.5 伤害步骤结束时

- **战斗破坏的怪兽送去墓地**
- "被战斗破坏时"、"战斗破坏对方怪兽时"的效果
- "直到伤害步骤结束时"持续适用的效果在此终止

---

### 3. 伤害步骤的发动限制

**伤害步骤内，原则上只能发动以下效果：**

| 允许发动的效果 | 示例 |
|---|---|
| 反击陷阱（速度 3） | 神之宣告 |
| 使卡片/效果发动无效的效果 | 我身作盾 |
| 增减攻击力/守备力的效果（限伤害计算前） | 禁忌的圣枪 |
| 自身反转/特殊召唤成功/被破坏时等诱发效果 | 里侧怪兽被翻开反转 |
| 必发效果 | — |
| 自身以外被战斗/效果破坏诱发的效果 | — |

#### 3.1 不能发动的效果

- 灰流丽等诱发即时效果（速度 2）：**不能**
- 通常魔法/速攻魔法（非上述允许类型）
- 普通陷阱（非反击陷阱）
- 大部分怪兽的起动效果

> **case_015**：龙骑兵团的效果在伤害步骤能发动吗？→ 裁定：它在伤害步骤可发动（属于自身相关的诱发效果）

---

### 4. 伤害计算相关的特殊规则

#### 4.1 攻击力变化效果的处理顺序（伤害计算时）

规则规定的处理优先级：
1. 先适用持续的攻击力变化
2. 再适用「攻击力变成」类效果
3. 最后适用「攻击力上升/下降」类效果

#### 4.2 战斗破坏确定

- 在伤害计算时确定被战斗破坏
- 但怪兽延迟到伤害步骤结束时才送墓
- 从确定破坏到送墓之间：怪兽仍在场上，但永续效果不再适用
- 替代破坏（如"把这张卡破坏作为代替"）在确定破坏时决定是否适用

---

### 5. 伤害步骤裁定案例

| 场景 | case | 核心裁定 |
|---|---|---|
| 龙骑兵团在伤害步骤发动效果 | case_015 | legal — 伤害步骤内可发动自身效果 |
| 编号38 在伤害步骤发动效果 | case_026 | illegal — phase_or_step_restriction |
| 灾难兽与大地鼹鼠伤害步骤开始时 | case_035 | illegal — 效果处理规则不满足 |
| 伤害计算时攻击对象与伤害计算 | case_026 | 涉及 attack_type 限制 |

## 12 — 特殊裁定概念

*（源：`docs/llmstudy/12-special-concepts.md`）*

> **撰写日期**：2026-07-28
> **来源**：P0 KONAMI Q&A + P2 `ocg-rule` + 项目 case 分析
> **对应项目**：多个 case 的`effect_resolution_rule`、`external_restriction`、`summon_condition`

---

### 1. 苏生限制（Rebirth Restriction）

#### 1.1 核心规则

特殊召唤怪兽必须先通过**正规手续**出场一次，之后才能用其他效果从墓地/除外区特殊召唤。

- **正规手续**：融合/S/X/连接怪兽 = 对应召唤方式
- 仪式怪兽的正规手续 = 仪式召唤
- 部分怪兽的特殊召唤条件 = 其正规手续

#### 1.2 失去正规履历

正规出场后，如果怪兽：
- 回到卡组或手牌等非公开场所 → **失去正规履历**
- 回到表侧额外卡组（灵摆怪兽） → P召唤被无效 → 失去正规履历

#### 1.3 无视召唤条件

"无视召唤条件特殊召唤"的效果可以绕过召唤限制和正规履历要求。但前提是怪兽的文本中没有"不能特殊召唤"的限制。

> **case_036**：关键裁定——无视召唤条件的效果仍要求怪兽有正规出场履历（苏生限制）。`illegal / summon_condition`

---

### 2. 替代破坏（Replacement Destroy）

#### 2.1 机制

部分卡可以"把这张卡破坏作为代替"来保护其他卡不被破坏。

例如：
- "六武众"怪兽 → 用其他六武众代替破坏
- "失落世界" → 用恐龙族通常怪兽代替破坏

#### 2.2 替代破坏的适用时点

在**破坏确定时**决定是否适用。不是在破坏效果发动时，而是在效果处理确定破坏结果时才适用。

> **case_034**：食魂窃蛋龙的对象被失落世界的替代破坏效果保护后，后续处理是否仍然适用？→ `illegal / effect_resolution_rule`
> **case_039**：替代破坏不能选择不受效果影响或不会被破坏的卡。

---

### 3. 卡片视为（Treated As / Name Change）

#### 3.1 规则

部分卡在场上时，卡名视为其他名字：

- "黑衣龙·阿尔比昂" → 场上卡名视为"阿尔白斯之落胤"
- "传说的都市 亚特兰蒂斯" → 卡名视为"海"

#### 3.2 裁定影响

- "场上卡名视为"的效果**不改变原本卡名**
- 硬限制（此卡名 1 回合 1 次）基于**原本卡名**
- 但对"指定卡名"的效果（如"从卡组把 1 只「阿尔白斯之落胤」特殊召唤"），场上视为同名 → 不影响"从卡组"等条件

> **case_009**：龙引导呼笛检索场上的"视为阿尔白斯"的卡，能从卡组特召真正的阿尔白斯吗？→ `legal`（视为同名不属于"同名卡在场"的限制—取决于效果文本的具体措辞）

---

### 4. Cost 替代去向

#### 4.1 灵摆怪兽的送墓

场上灵摆怪兽被送墓时：**不去墓地 → 表侧表示加入额外卡组**。

这导致：需要"送墓"作为 cost 的效果，灵摆怪兽**不能作为 cost**（因为实际去向不是墓地）。

> **case_024**：场上灵摆怪兽不能送墓为 cost → `illegal / cost_payability`

#### 4.2 宏观宇宙等除外环境

"宏观宇宙"效果适用中：所有送墓的卡改为除外。

→ 需要"送墓"作为 cost 的效果**不能发动**（因为 cost 实际无法支付）

> **case_013**：宏观宇宙下舍弃至墓地为 cost → `illegal / cost_payability`

---

### 5. 发动被无效后的规则（2020 修订）

#### 5.1 召唤被无效

2020.04 规则后：
- 被无效的通常召唤 → **不计入**本回合通常召唤次数
- 被无效的特殊召唤 → **不计入**"1 回合只能有 1 次特殊召唤"
- 被无效的召唤 → 不触发"召唤成功时"的效果

#### 5.2 效果发动被无效

- 被"神之宣告"无效 → 整个发动不存在 → 不消耗"1 回合 1 次"（仅限"只能**发动**1 次"的限制）
- 但如果是"只能**使用**1 次"的限制 → 发动被无效仍然消耗（更严格的日文措辞）

---

### 6. 暂时除外与返回

#### 6.1 规则

"直到结束阶段除外""直到效果处理完毕除外"等暂时除外的效果：

- 除外期间 → 卡在除外区，不在场上
- 返回时 → 回到原来的位置（如可用）
- 除外期间发生的事件（如卡通世界被破坏）→ **不追溯**影响返回后的怪兽

> **case_040**：卡通怪兽暂时除外期间，卡通世界被破坏。返回后卡通怪兽是否因卡通世界的自毁效果被破坏？→ `illegal`（暂时除外期间的事件不追溯）

---

### 7. 连锁处理后的诱发窗口

#### 7.1 规则

整条连锁处理完毕后，满足发动条件的诱发效果可以在此时发动。这**不是**"同一连锁中"而是在连锁处理完成后另开新连锁。

> **case_031**：卢恩神碑之泉的效果——整条连锁处理后另开时点触发 → `legal`

---

### 8. 转移战斗伤害

#### 8.1 机制

部分卡可以改变战斗伤害的承受方或方向：

- "次元壁"：对方怪兽的战斗伤害由对方自己承受
- 代替对方玩家承受伤害的效果

> **case_047**：次元壁转嫁伤害后，三进制术士的效果是否触发？→ `illegal`（被转嫁的伤害不算"给与战斗伤害"给对手）

---

### 9. 多●效果的处理

#### 9.1 规则

有多项●的效果，如果某项**不依赖发动卡自身**，即使发动卡离场，该项仍可正常处理。

> **case_008**：天救龙离开手牌后，不依赖于自身的分项处理仍然适用 → `legal`

---

### 10. 这些概念在本项目中的分布

| 概念 | 涉及 case | failed_check |
|---|---|---|
| 苏生限制 | case_036 | summon_condition |
| 替代破坏 | case_034, case_039 | effect_resolution_rule, external_restriction |

## 13 — 官方裁定体系

*（源：`docs/llmstudy/13-official-ruling-system.md`）*

> **撰写日期**：2026-07-28
> **来源**：P0 KONAMI 官方 Q&A 数据库 + 项目 `docs/PROJECT_CONTEXT.md`
> **对应项目**：`required_sources` 字段、证据契约、fid/cid 体系

---

### 1. KONAMI 官方 Q&A 数据库

#### 1.1 数据库结构

KONAMI 维护了官方卡片数据库和 Q&A 系统：

| 数据库 | URL | 语言 |
|---|---|---|
| **日文官方 DB** | `https://www.db.yugioh-card.com/yugiohdb/` | 日文 |
| **简中官方 DB** | `https://www.db.yugioh-card-cn.com/` | 简中 |

每张卡在日文 DB 中有：
- 卡片详情页（效果文本、属性、卡包信息）
- Q&A 列表（该卡相关的官方裁定）
- 补充页面（`cid:XXXXX#supplement`，部分卡有额外的裁定说明）

#### 1.2 裁定标识符

| 标识符 | 格式 | 说明 | 本项目 source_type |
|---|---|---|---|
| **cid** | `cid:数字` | Card ID — 指向卡片详情页 | `official_card_text` |
| **fid** | `fid:数字` | FAQ ID — 指向具体 Q&A 条目 | `official_ruling` |
| **cid#supplement** | `cid:数字#supplement` | 卡片的补充裁定页面 | `official_ruling` |
| **rulebook** | `rulebook:标识` | 官方规则书引用 | `official_rulebook` |

---

### 2. 裁定为什么"不过期"

#### 2.1 裁定的本质

KONAMI 官方 Q&A 是**对游戏规则和卡片文本的权威解释**，不是随环境变化的"策略建议"。一条裁定回答的是一个特定的规则交互问题。只要：

1. 涉及的**卡片效果文本没有 errata（修订）**
2. 涉及的**游戏规则没有修订**

→ 该裁定就仍然有效。裁定数据库中的 `source_updated_at` 记录的是该条目最后一次被 KONAMI 更新/添加的日期。**没有更新意味着裁定没有变化**。

#### 2.2 裁定何时会变化

| 变化原因 | 示例 |
|---|---|
| 卡片文本 errata | 卡的効果文本被修订（如"处刑人-摩休罗"2020 年新文本） |
| 规则修订 | 2020.04 大师规则修订导致部分旧裁定被替换 |
| 新裁定覆盖旧裁定 | KONAMI 发布更精确的解释 |

> 因此，**不存在"太久远的裁定自动失效"**。如果一张卡从 2017 年到 2026 年没有被 errata，其裁定依然有效。

---

### 3. 裁定来源的权威层级

| 层级 | 来源 | 权威性 | 本项目中对应 source_type |
|---|---|---|---|
| 1 | KONAMI 官方 Q&A 数据库 | 最高 | `official_ruling` |
| 2 | KONAMI 官方规则书 | 最高 | `official_rulebook` |
| 3 | KONAMI 官方卡片详情页（卡的效果文本） | 最高 | `official_card_text` |
| 4 | KONAMI 官方新闻/公告 | 高 | — |
| 5 | 二手材料（B站、Reddit、贴吧） | 参考 | `secondary_reference` |

> 本项目**证据契约**要求：每条正式 case 至少含 1 个 `official_card_text` + 1 个 `official_ruling` 或 `official_rulebook`。

---

### 4. 日文原文 vs 简中翻译

#### 4.1 权威性差异

- **日文原文**：裁定原文，最高权威，不可争议
- **简中翻译**：翻译版本，权威性由官方运营方保证。部分卡无简中裁定翻译时，需引用日文原文
- **简中官方卡片文本**（`db.yugioh-card-cn.com`）：等于日文原文的权威性

#### 4.2 本项目的语言覆盖规则

校验器（`check_jsonlschema.py`）强制要求每条 case 同时包含：
- `ja` (日文) 的 `official_card_text`
- `zh-CN` (简中) 的 `official_card_text` 或经批准的 `secondary_reference`（用于确实无简中官方正文的卡）

---

### 5. 二手材料的定位

#### 5.1 允许的使用方式

- `secondary_reference`（`source_type`）
- 只能作为**补充解释**，不能成为**唯一裁定依据**
- 来源可以是：B站裁定讲解视频、YGOrganization 翻译、贴吧精华帖等

#### 5.2 本地 cards.cdb 的使用

对于无法在 KONAMI 简中官方 DB 中访问的卡，允许使用：

```json
{
  "source_type": "secondary_reference",
  "authority": "local_cards_cdb",
  "url": "local-cdb://cards.cdb/texts/99999999",
  "language": "zh-CN"
}
```

> 本地 CDB 来源**不能**伪装为 `official_card_text`。

---

### 6. 裁定数据库的实际查询流程

当为本项目新增一条 case 时：

1. 确定涉及的卡片 → 用日文 DB 搜索卡名
2. 查看卡的 Q&A 列表 → 找对应的裁定条目
3. 记录 `fid`（FAQ ID）和 `source_updated_at`
4. 在日文 DB 和简中 DB 中都确认卡片详情页可访问
5. 如果简中 DB 无该卡 → 寻找 `local-cdb://` 补源或替换候选

---

### 7. 与本项目的关联

本项目的 `gold_answer.required_sources` 字段完整实现了这套证据体系。每条 case 的证据链都是可追溯、可验证的，URL 指向 KONAMI 官方域名（`yugioh-card.com`），ID 格式符合 `fid:数字` 或 `cid:数字`。

## 14 — 裁定判断方法论

*（源：`docs/llmstudy/14-judgment-methodology.md`）*

> **撰写日期**：2026-07-28
> **来源**：项目 `docs/task_scope.md` + `docs/schema.md` + 58 条 case 的分析
> **对应项目**：`gold_answer.label`、`failed_check`、`reasoning_steps`、`missing_info`

---

### 1. 判断流程

本项目的裁定判断遵循 **9 步标准流程**：

```
1. 存在合法操作窗口？
   NO → illegal / activation_window
   YES ↓
2. 操作能在该窗口发动/执行？
   NO → illegal / activation_window
   YES ↓
3. 发动/召唤/攻击条件是否满足？
   NO → illegal / activation_condition (或 summon_condition)
   YES ↓
4. Cost 是否可支付？
   NO → illegal / cost_payability
   YES ↓
5. 对象是否合法（发动时+处理时）？
   NO → illegal / target_legality
   YES ↓
6. 是否违反次数限制（一回合一次等）？
   YES → illegal / once_per_turn
   NO ↓
7. 是否受持续效果/召唤限制/攻击限制/区域限制/伤害步骤限制等约束？
   YES → illegal / external_restriction (或 phase_or_step_restriction / zone_availability)
   NO ↓
8. 效果处理是否按声明方式适用？
   NO → illegal / effect_resolution_rule
   YES ↓
9. 输出结论 + 推理链 + 证据
```

---

### 2. 输出标签（Label）语义

| 标签 | 含义 | 何时使用 | missing_info |
|---|---|---|---|
| `legal` | 操作合法 | 所有检查点通过 | 空数组 |
| `illegal` | 操作不合法 | 某个检查点失败 | 空数组 |
| `depends` | 信息不足 | 缺少关键事实无法判断 | **非空** |
| `invalid_question` | 超出任务边界 | 不属于规则合法性任务 | 空数组 |

#### 2.1 为什么前 50 条 case 没有 `depends`，而后补了 2 条示范

游戏王的裁定在**完整场景已知**的前提下是非黑即白的：
- 给了你 pre_state + attempted_operation → 所有判断要素都在数据内
- 不存在"这个情况取决于玩家选择"——因为 attempted_operation 已经固定了玩家的选择
- `depends` 是留给"pre_state 信息确实不完整"的场景

前 50 条 case 的 pre_state 信息都足够判断，因此没有 depends。为示范该标签的用法，
case_057 与 case_058 刻意留白关键信息：

- **case_057**：对方盖卡内容未知，雷击的发动本身合法但破坏结果无法确定 → `depends / unknown_missing_info`，`missing_info` 记录"对方盖卡的内容"。
- **case_058**：缺少对方本回合是否已使用过增殖的 G 的信息 → `depends / unknown_missing_info`，`missing_info` 记录一次使用记录。

---

### 3. failed_check 枚举详解

| failed_check | 检查点 | 典型场景 | 对应 case |
|---|---|---|---|
| `activation_window` | 发动窗口 | 召唤成功时不能先发动起动效果、优先权在对方、非主要阶段不能发速度1效果 | 006, 011, 021, 022 |
| `activation_condition` | 发动条件 | 卡片/效果的发动条件不满足 | 004, 005, 027, 042, 047, 050 |
| `chain_speed` | 连锁速度 | 速度1不能连锁速度2、反击陷阱只能被反击陷阱连锁 | 012 |
| `cost_payability` | Cost 可支付性 | 宏观宇宙下不能送墓cost、灵摆怪兽不能送墓、手牌只有发动卡自身 | 013, 024, 054 |
| `target_legality` | 对象合法性 | 发动时/处理时对象不合法、对象离场 | 025, 048 |
| `card_location` | 卡片位置 | 卡不在应有位置发动 | 055 |
| `once_per_turn` | 次数限制 | 一回合一次已使用、●项目被无效仍算选择 | 007, 037 |
| `phase_or_step_restriction` | 阶段限制 | 不能在该阶段发动（如伤害步骤限制） | 026 |
| `summon_condition` | 召唤条件 | 米德拉什限制、苏生限制 | 016, 036 |
| `material_legality` | 素材合法性 | 融合/同调/超量/连接素材不满足 | 056 |
| `zone_availability` | 区域可用 | 怪兽区满、灵摆召唤区域冲突 | 046 |
| `effect_resolution_rule` | 效果处理规则 | 离场后效果无效、持续效果影响处理、替代破坏后处理 | 002, 018, 034, 035, 040 |
| `external_restriction` | 外部限制 | 王谷限制、卡通世界限制、替代破坏限制、不能盖放限制 | 029, 039, 043, 052, 053 |
| `unknown_missing_info` | 信息缺失 | 无法判断具体哪个 check 失败 | 057, 058 |

---

### 4. 两类 task_type 的判断差异

#### 4.1 operation_legality_judgment（45 条）

判断"能不能发动/召唤/攻击"：
- pre_state 通常处于开放状态或连锁构建中
- 重点检查：窗口、条件、cost、对象（发动时）、次数限制、外部限制

#### 4.2 effect_resolution_judgment（13 条）

判断"效果处理是否能按声明方式适用"：
- pre_state 通常处于连锁处理中（`state_timing: before_resolving_C1`）
- 必须有 `resolution_history` 记录已处理的连锁块
- 重点检查：处理时对象是否仍合法、是否符合效果处理规则、已处理的连锁结果对当前处理的影响

---

### 5. reasoning_steps 的撰写规范

每条 case 的 `reasoning_steps` 是逐步推理链：

1. **陈述已知事实**：pre_state 的 key facts
2. **引用规则或裁定**：fid/cid 的具体内容
3. **检查一致性**：fact vs rule
4. **得出结论**：legal/illegal + failed_check

---

### 6. 与本项目的校验对应

`check_jsonlschema.py` 中有多种校验直接映射到判断方法论：

| 校验 | 对应方法论 |
|---|---|
| `task_type` 与 `operation_type` 一致性 | resolve_effect ↔ effect_resolution_judgment |
| `chain_response_to` 引用有效性 | 窗口/连锁引用 |
| `resolution_history` 完整性与逆序 | 效果处理判断的前提 |
| case_003/005 防回退 | 关键裁定的建模正确性 |

### 2. 已覆盖操作类型详解

#### 2.1 activate_effect（发动效果）

**最多使用的操作类型**（24 条 case）。

典型场景：
- 手坑发动（灰流丽、效果遮蒙者、尼比鲁）— case_001/006/016
- 墓地效果发动（凤凰人）— case_004
- 场上效果发动（冰剑龙、S:P、赫焉龙）— case_005/007/003
- 卡组/手牌间接效果发动（烙印相关）

关键必填字段：`effect_id`、`activation_location`

#### 2.2 resolve_effect（效果处理）

13 条 case，对应 `task_type: effect_resolution_judgment`。

典型场景：
- 泡影同纵列无效已离场卡（case_002）
- 天救龙离场后分项处理（case_008）
- 墓穴指名者对象离场后的处理（case_025）
- 大搜捕对象变里侧后的处理（case_020）

关键必填字段：`effect_id`、`chain_id_to_resolve`、`declared_resolution`

#### 2.3 activate_card（发动卡片）

12 条 case。

典型场景：
- 魔法卡发动（增援、闪刀启动、联合机库）— case_001
- 陷阱卡发动（神之通告、神之警告）— case_004/023
- 灵摆怪兽作为魔法发动 — case_027

关键必填字段：`activation_location`

#### 2.4 declare_attack（攻击宣言）

2 条 case：case_003（S:P限制下直接攻击）、case_043（卡通世界被破坏后卷回）

关键必填字段：`attack_type`（`direct_attack` 或 `attack_monster`）、`card_location`、`card_zone`

#### 2.5 special_summon（特殊召唤）

2 条 case：case_029（王谷下墓地自身特召手续）、case_046（灵摆召唤区域冲突）

用于判断特殊召唤本身是否合法（不是通过效果召唤，而是不入连锁的手续或 P召唤）。

#### 2.6 select_target（选择对象）

1 条 case：case_048（暗之咒缚降攻后选择对象）

用于单独判断"取对象"这一环节是否合法。与 `activate_effect` 的区别：这里是拆解了发动过程，聚焦于对象选择这一子操作。

### 3. 2026-07-28 补齐的操作类型

原先以下 4 种操作类型没有独立 case，现已各补 1 条示范。

#### 3.1 normal_summon（通常召唤）— case_051

被神之宣告无效的通常召唤**不计入**本回合通常召唤次数（2020.04 规则修订），
主要阶段 2 仍可再次通常召唤 → `legal`。

其余核心裁定场景（"不能通常召唤"限制下的效果召唤、上级召唤的祭品要求等）仍可作为扩充方向。

#### 3.2 set_card（盖放魔陷）— case_052

暗黑神鸟适用中"不能把卡盖放"，不能盖放魔法/陷阱卡 → `illegal / external_restriction`。

> 魔封之芳香限制下"不能发动"已由 case_027 覆盖，但"盖放本身"的限制由本条 case 独立判断。

#### 3.3 set_monster（盖放怪兽）— case_053

同样在暗黑神鸟限制下，不能盖放怪兽 → `illegal / external_restriction`。
盖放占用每回合 1 次的通常召唤名额，与 §3.1 的次数规则呼应。

#### 3.4 pay_cost（支付 cost）— case_054

手牌只有发动卡自身时，不能支付"舍弃 1 张手牌"的 cost → `illegal / cost_payability`。

> 与 case_013/case_024 的区别：那两条在 `activate_effect`/`activate_card` 操作中检查 cost 可支付性；
> case_054 单独问"这个 cost 能否支付"而不管发动本身。
