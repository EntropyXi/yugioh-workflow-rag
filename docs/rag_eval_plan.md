# RAG 检索评测集：三级难度标准与生成计划

## 一、目标

为 50 条 gold cases 各配 2-3 个自然语言检索题目，共计约 120 条 eval 条目，按三级难度分层，用于评测 RAG 系统在游戏王裁定检索场景下的表现。

评测维度：recall@1 / recall@3 / recall@5 / MRR，按 difficulty 分组报告。

---

## 二、三级难度定义

### EASY —— 关键字即可命中

**定义**：题目包含该 case 独有的、高度辨识度的卡名或场景短语，任何具备基础 BM25 能力的检索系统都应能命中正确 case。

**判定标准（满足 ≥3 条即为 easy）**：

| # | 标准 | 说明 |
|---|------|------|
| E1 | 题目中出现了该 case 在全部 50 条 gold cases 范围内独有的标志性卡名（不因后续 case 批量生成而退化） | 如"灰流丽"仅在 case_001 出现，"冰剑龙"仅在 case_007 出现。注意"尼比鲁"在 case_006 和 case_016 均出现，不能作为 E1 依赖。后续 batch 生成时需重新检查已标注为 easy 的条目 |
| E2 | 提问场景是该卡最著名的裁定争议 | 如灰流丽能不能连锁、凤凰人能不能用神之通告无效——社区高频问题 |
| E3 | 正确答案是玩家直觉就能猜到的 | legal 或 illegal 的判定符合大多数正常玩家的第一反应 |
| E4 | 题目表述是"A 能不能做 B"的简单疑问句 | 没有任何分层条件或多重假设 |
| E5 | 与其他 case 的 Jaccard 相似度 < 0.15 | 换卡名换场景后不可能和其他 case 撞 |

**示例**：

> `eval_001a` [easy]: 对方发动增援把卡从卡组加入手牌，我能连锁发动灰流丽吗？
> → 灰流丽只在 case_001 出现，场景为该卡最经典用法，单句疑问。

> `eval_004a` [easy]: 命运英雄毁灭凤凰人上回合被炸了，这回合准备阶段自己从墓地跳回来。我有盖着的神之通告，能在它跳回来的时候发动无效那个特召吗？
> → 凤凰人只在 case_004 出现，场景为经典裁定争议。

> `eval_006a` [easy]: 我连接召唤做完，刚把怪放到场上，对面就马上扔陨石。我还没说要不要发动效果呢，他能抢先吗？
> → 陨石只在 case_006 出现（作为 attempted card），场景为陨石优先权经典问题。


### MEDIUM —— 需要语义理解，不能纯靠关键字

**定义**：题目可能不包含唯一标识性卡名，或涉及 2+ 个游戏机制的交互，或卡名出现在多个 case 中。需要检索系统理解裁定语义而不只是匹配卡名字符串。

**判定标准（满足 ≥3 条即为 medium）**：

| # | 标准 | 说明 |
|---|------|------|
| M1 | 题目中卡名出现在 ≥2 个 case 中，必须靠场景细节区分 | 如"无限泡影"出现在 case_002 和 case_015 等 |
| M2 | 涉及 ≥2 个规则维度的交互 | 如同时涉及优先权 + 诱发时机、同纵列 + 离场有效 |
| M3 | 题目使用术语精确但场景具有通用性 | 如讨论"效果产生的特召 vs 召唤手续"，不指名具体卡也可能对应多个 case |
| M4 | 裁定结果与玩家直觉相反 | legal 但玩家通常以为 illegal，或反之——需要理解深层规则 |
| M5 | 题目是泛化场景描述而非点名具体卡 | 如"对方检索一张卡，我发动手坑"而非"对方发动增援，我连锁灰流丽" |

**示例**：

> `eval_001c` [medium]: 对手的怪兽效果从卡组检索了一张魔法卡，灰流丽的效果能不能对应？效果文本写的是"从卡组把卡加入手牌"，检索魔法的怪兽效果算不算？
> → 灰流丽仍是唯一卡名（easy 前提），但加了一层概念泛化——不是问能不能连锁"增援"而是泛化到"检索魔法的怪兽效果"，需要理解灰流丽的裁定适用边界。

> `eval_003a` [medium]: 我的电子界到临者@火灵天星不受其他卡效果影响，但 S:P 小夜骑士发过效果说"自己怪兽不能直接攻击"。到临者能不能无视这个限制直接打脸？
> → 涉及"对怪兽的限制 vs 对玩家的限制"这一概念区分，是社区高频误区的核心。

> `eval_008b` [medium]: 有多个●项的效果，自身在发动后处理前离场了，那些不依赖自身的●项还能不能正常处理？
> → 完全泛化——未点名天救龙，而是抽象为"有多个●项的效果"。需要 RAG 从语义上匹配到 case_008。


### HARD —— 刻意构造歧义，测试区分度

**定义**：题目故意使用与另一个 case 重叠的术语或场景描述，或把问题抽象为原理级提问。命中的前提是检索系统理解了裁定之间的**细微语义边界**，而不是靠卡名或场景关键词。

**判定标准（满足 ≥3 条即为 hard）**：

| # | 标准 | 说明 |
|---|------|------|
| H1 | 题目中出现的卡名/术语在 ≥3 个 case 中均有出现 | 如"cost""除外""无效""特殊召唤"——高频通用词 |
| H2 | 题目场景被设计为容易误检索到另一个具体 case | 两个 case 讨论相似问题但裁定结论不同 |
| H3 | 用完全不同的措辞描述同一个裁定原理 | 测试语义泛化——看 RAG 能不能识别"换了个说法但问的是同一件事" |
| H4 | 涉及 ≥3 个规则维度的叠加或边缘交互 | 多个罕见规则同时作用 |
| H5 | 题目中不出现任何具体卡名，完全用规则概念描述 | 只能靠裁定语义检索 |

**示例**：

> `eval_002c` [hard]: 假设我 C1 发动魔法，对面 C2 在我同纵列发了泡影，然后 C3 有卡把我的魔法炸了。C1 处理时魔法已经不在场上了，泡影还能无效它吗？
> → 完全泛化——不点名"烙印之气炎"或"落胤与圣女"，抽象为"魔法""泡影""炸了"。如果系统只学了"烙印之气炎+泡影=无效"，遇到这个泛化版本可能检索到错误的 case。

> `eval_005b` [hard]: IP 莱娜的效果写的是"以包含此卡在内的自己场上怪兽作为素材进行连接召唤"。这是"进行连接召唤的效果"还是"把怪兽特殊召唤的效果"？有没有人能解释一下区别？
> → 这个问题的核心概念——"进行 XX 召唤的效果"vs"把怪兽特殊召唤的效果"——是 OCG 裁定的核心区分，但 case_005 是数据集中唯一覆盖此概念的。如果 RAG 不理解这个语义，会被关键字"特殊召唤""效果"带偏到大量其他 case。

> `eval_010a` [hard]: 对面开了看透心灵之眼公开我手牌。我用闪刀姬零变篝，篝的诱发和手牌露世的诱发同时触发。露世在手牌但被公开了，它的效果还算"隐藏区域"的吗？能不能和篝自排连锁？
> → 涉及 3 个冷门规则交集（公开手牌、隐藏区域诱发时机、自排连锁规则），且裁定结论反直觉。泛化版本容易被检索到其他同时触发的 case。

> `eval_007b` [hard]: 冰剑龙②效果文本："此卡名的此效果 1 回合仅可使用 1 次"。处理时冰剑龙已变成里侧。里侧状态下适用的"下回合不可使用"限制，在结束阶段被翻开后是否仍有效？
> → 虽点名冰剑龙，但核心问题是"里侧状态下获得的效果限制，翻开后是否保留"——这个原理性提问如果泛化为"怪兽被盖了又翻开，一回合一次的限制还在不在"，就需要 RAG 理解裁定本质而非卡名匹配。




> **排他规则**：当一条题目同时满足 ≥3 条 medium 标准和 ≥3 条 hard 标准时，优先判为 hard。此规则基于：hard 的核心价值是测试语义区分度，一旦题目具备了 hard 级别的歧义性，就不应因同时满足多项 medium 标准而降级。

## 二A、难度标注前瞻规则

- 在后续 batch 生成时，每次新增 case 后需运行卡名唯一性检查脚本，确认已有 easy 条目所依赖的卡名是否因新增 case 而不再唯一。
- 若某个已标注 easy 的条目所依赖的卡名在新 batch 中被另一个 case 也引用，该条目应重新评估是否降为 medium。
- eval_006a 已记录前瞻风险注释（尼比鲁同时为 case_016 核心卡），作为此类标注的模板。

## 三、难度配比目标

| | Easy | Medium | Hard |
|---|---|---|---|
| 占总条目比例 | ~30% (~36条) | ~45% (~54条) | ~25% (~30条) |
| 每条 case 最少 | 1 | 1 | 0 |
| 每条 case 最多 | 2 | 2 | 2 |

- 所有 case 至少配 1 easy + 1 medium
- hard 只配给有深度区分价值或涉及冷门原理的 case（预估 ~25-30 条 case 有 hard 题目）
- 有明显"姐妹 case"的（两个 case 讨论相似场景但结论不同），必须至少配 1 hard 做区分测试

---

## 四、与评测流程的关系

```
eval 条目 (question) → RAG retrieval → top-k ranked case_ids → 比对 gold_case_id
```

- Easy 题目的作用：baseline 验证——如果 easy 的 recall@1 < 0.9，说明索引或 embedding 有基础问题。
- Medium 题目的作用：真正评测检索质量，调参主要看 medium 的表现。
- Hard 题目的作用：区分优秀系统和普通系统的分水岭——hard 的 recall@3 最能体现检索系统的语义理解能力。
